# 文件服务器配额模拟器

地方志办几十个乡镇的编纂组共用一台文件服务器：一个组集中上传高清扫描时，其他组连新建一个文档都会失败；之前用系统配额去限，结果改名、移动文件全都报错。这个模块把配额逻辑从内核里拿出来，在程序内模拟文件系统，按 **用户 / 组 / 目录树** 三个维度同时限制 **空间** 和 **文件数**，每个维度都有 **软限** 和 **硬限**，并带一个查看用量的网页。

- 纯内存模拟，不碰真实文件系统；所有操作走 `quota.Engine` 的 API。
- 网页展示每个用户、组、目录树的已用空间、文件数、软/硬限额、宽限期剩余时间，以及每一次被拒绝的操作和原因。
- 自带一个固定种子的随机压测器：按用户/组/目录树做几百万次创建、写入、截断、删除、移动、改属主/属组、建硬链接，时间随机快进跨过宽限期，每一步之后都用独立扫描复核各维度用量，并校验"任何时刻没有一处超过硬限额、所有被拒操作都确实会超限"。

## 快速开始

```bash
go test ./...                       # 单元测试 + 随机压测（含确定性检查）
go run ./cmd/quotaserver            # 起面板：http://localhost:8080/
go run ./cmd/quotaserver -simulate -steps 3000000
```

面板上可以修改限额、延长某个账户的宽限期；每次改动都记录操作人、时间和具体改动，在页面上可见（`/api/report` 的 `activity`）。也可以推进"模拟时钟"让宽限期走完：

```bash
curl -X POST 'http://localhost:8080/api/clock?advance_seconds=3600'
```

模拟器参数（数字越大越慢，默认值即可跑百万级）：

```bash
go run ./cmd/quotaserver -simulate \
  -steps 3000000 -seed 20260101 \
  -users 48 -groups 12 -townships 24 \
  -grace-hours 24 -max-live 700 -check-every 20000
```

`-limit-scale 0.2` 会把所有限额按比例缩小，让小规模模拟也能频繁触到软/硬限（测试用）。`-json` 输出结构化结果，`-max-wall 10m` 限时。

## 配额语义

一个文件同时计入 **属主用户**、**属组**、**所在目录树** 三处；三处任何一处超限都拒绝。

### 软限与宽限期

每个维度、每种资源（空间、文件数）各有软、硬两个限额（`Limit{Soft, Hard}`，`0` 表示不限）。

- 用量超过软限仍可写，同时开始宽限期（账户级 `Grace`，默认 24 小时）。
- 宽限期到了还没降回软限以下，软限就变成实际执行的天花板（`EffectiveLimit`），此后任何会让用量继续超过软限的写入都会被拒绝，直到用量降回软限以下。
- 宽限期用"惰性计算"：没有后台定时器，每次探测限额时按模拟时钟判断是否已过期，因此时间快进、停机都不会漏掉。边界是 `now >= deadline` 即失效（见 `Account.EffectiveLimit`）。
- 软限只在"软限 > 0 且低于硬限"时才有意义；软限 ≥ 硬限或没有硬限时恒不触发（`Account.SoftEffective`）。
- 管理员可以临时给某个账户延长宽限期（`Engine.GrantGrace`）：正在跑的宽限期顺延；已经过期的则从"现在"重新计时，即恢复按硬限执行，直到新的截止时间。

### 超过硬限

- 新建、mkdir、symlink、移动、改属主/属组：需求量（1 个 inode，或整个子树的 inode 数 + 字节数）中对应最多的一方放不下，就**当场整笔拒绝**，不做任何改动。
- 写入、增长型截断：**只写进没超的那部分**，并返回实际写入量（`Result.Written` / `Result.Size`），同时带 `*QuotaError` 说明哪一处被拒、差额多少。已经超出硬限的账户（例如宽限期过期后仍在软硬限之间）容量按 0 处理。
- 三种维度按 用户 → 组 → 目录树 的顺序检查，同维度内先查文件数、再查空间；拒绝记录里写明是哪一个账户、哪一种资源。

### 目录树

- 目录树按"目录编号"继承：`Mkdir(..., treeID)` 创建一个树根，其后代全部计入该树，直到遇到下一个树根。没挂任何树的目录计入隐式的 `root` 树。
- 文件移动到另一棵树时，把整个被移动子树的用量从旧树转到新树；新树放不下就拒绝移动，旧树、新树都不变。移动目录时子树里嵌套的树根不会被吞并，它们连同其用量一起搬走。
- 同一文件有多个硬链接时，硬链接必须和文件在同一棵树内（否则"文件属于哪棵树"就不再唯一，无法逐文件对账）。这类跨树硬链接、以及会把多链接文件拆到两棵树上的跨树目录移动，都作为**结构错误**拒绝（`*OpError`），不记作配额拒绝。

### 其他操作

- 改属主、改属组：用量跟着转移；新的一方放不下就拒绝，旧的一方也保持不变。
- 目录和符号链接各算一个 inode；符号链接不占空间。
- 删除、缩小型截断立即退还用量；文件的最后一个硬链接删除后才退还。
- 目录必须为空才能删除（否则结构错误）。

## 一个文件的三处归属

```
        owner user account ────────────┐
        owner group account ───────────┼──► 每次操作都按这三处分别探测
        directory tree account ────────┘
```

因此"一个组猛传"会被组配额挡住，"某个乡镇目录塞满"会被目录树配额挡住，"某个人的账号写满"会被用户配额挡住，互不牵连。

## 校验

### 每步都做的扫描核对

`Engine.VerifyScan` 不读运行中的计数器，而是遍历所有存活 inode，按每个 inode 记录的三处归属重新求和，再与账户计数比对；同时检查没有账户超过硬限、没有负数用量。模拟器每一步之后都会调用它，所以任何一次漏记/多记都会立刻被发现。

每一笔拒绝还会对照操作前的独立扫描结果复核：

- 拒绝记录的 `Used` 等于操作前该账户的扫描用量；
- 拒绝记录的 `Limit` 等于按模拟时钟算出的当时执行限额；
- `Used + Demand > Limit` 确实成立（截断写入时按实际写入量折算，即 `Used + Demand - Written > Limit` 仍成立）；
- 记录里"生效的是软限还是硬限"与当时宽限期状态一致。

### 定期做的结构核对

`Engine.VerifyState` 额外从根目录遍历整棵目录树，按继承规则重新推导每个 inode 所属的树并和记录比对，检查每个 inode 可达、目录项数与硬链接数一致、每个位置都真实存在。压测器每 `CheckEvery` 步做一次，结束时再做一次。

### 固定的随机负载

`quota/sim` 用 `math/rand` 固定种子；同样的参数（种子、账户数、步数、限额缩放、宽限期）得到完全一致的结果（`TestDeterministic`）。时间推进有两种：平时每步推进 0 到宽限期/8 的随机时长，另有约 0.1% 的步会一次跳过整个宽限期好几倍，保证宽限期过期/恢复都被覆盖。

每次运行结束会报告：总步数、拒绝次数、写入被截断次数、实际写入字节、各操作次数、最终扫描与结构校验结果。任何不一致都会作为 `Failures` 列出，`OK=false`。

## HTTP API

| 路径 | 方法 | 说明 |
| --- | --- | --- |
| `/` | GET | 用量面板 |
| `/api/report` | GET | 完整快照：三类账户、拒绝记录、审计记录、统计 |
| `/api/verify` | GET | 立即做一次全量扫描 + 结构校验 |
| `/api/limits` | POST | 改限额：`{"dim":"user","id":"编辑14","actor":"李主任","bytes":{"soft":…,"hard":…},"inodes":{…}}`；硬限低于当前用量会被拒绝 |
| `/api/grace` | POST | 延长宽限期：`{"dim":"tree","id":"tree-01","actor":"李主任","seconds":43200}` |
| `/api/clock` | GET/POST | 读取/推进模拟时钟：`?advance_seconds=3600` |

## 代码结构

```
quota/            配额引擎
  types.go        账户、限额、宽限期、拒绝/审计记录、快照类型
  engine.go       文件系统模拟 + 配额探测/记账 + 管理操作
  ring.go         有界日志的环形缓冲
  verify.go       独立扫描、结构校验、单条拒绝的算式复核

  sim/            固定种子的随机压测器
  server/         HTTP + 面板模板
cmd/quotaserver/  命令行入口、地方志办演示布局
```

## 已知边界

- 这是**模拟器**：`quota.Engine` 的 API 才是权威模型，没有对接真实 inode 或内核配额。要在真实文件系统上落地，需要把同一套探测/记账逻辑接到实际的 `create/write/truncate/rename/link/chown` 路径上。
- 目录树移动是"整棵子树"的原子操作：先校验目标树的容量再一次性转移，不为中途失败做回滚。
- 宽限期是惰性判定，没有后台任务；读取用量时才会按当前模拟时钟体现"已过期"。
- 硬链接不允许跨目录树，因此跨树移动多链接文件、或移动"含外部硬链接"的目录都会被结构拒绝；这是为了让"文件属于哪棵树"唯一、可逐文件对账。
